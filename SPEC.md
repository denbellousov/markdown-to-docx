# md2docx — спецификация v1.2.0

Локальный конвертер Markdown → DOCX. Главное — аккуратные заголовки и таблицы,
книжная и альбомная ориентация страниц. Один файл `md2docx.py` (переводы сообщений —
в `locales/<язык>.json`, без них всё по-английски), Python ≥ 3.10.
Зависимости (проверено на этих версиях): `python-docx` 1.2.0, `markdown-it-py` 4.0.0,
`Pillow` 11 (опционально, для замера ширины текста), `lxml` (ставится вместе
с `python-docx`). Новых не добавлять.

Стиль снят из XML эталонного документа Word 16 (далее — эталон). Значения ниже —
измеренные, не оценки; что досчитано по аналогии, помечено «экстраполяция».

## 1. Командная строка

```
python3 md2docx.py INPUT.md [INPUT2.md ...] [-o OUT.docx] [--landscape] [--no-auto-landscape] [--force] [--version]
python3 md2docx.py --fix-fonts FILE.docx [FILE.docx ...] [--force]
```

- Без `-o` результат пишется рядом с исходником: `doc.md` → `doc.docx`.
- `-o` допустим только при одном входном файле, иначе код выхода 2 и сообщение.
- `--landscape` — ориентация документа по умолчанию альбомная (маркеры её переключают).
- `--no-auto-landscape` — выключить автоальбомную ориентацию широких таблиц (§4.3).
- Коды выхода: 0 — успех; 1 — ошибка конвертации (нет файла, не читается и т. п.);
  2 — ошибка аргументов (argparse).
- Уточнено по итогам проверки: `-o`, указывающий на сам входной файл, — код 1 и
  сообщение, исходник не трогается; пустой `-o` — код 2. Непредвиденная ошибка на
  одном файле — `Ошибка: <файл>: внутренняя ошибка (<класс>: <текст>)`, код 1, остальные
  файлы пакета конвертируются.
- Сообщения — на языке интерфейса (1.1.0): исходные строки английские, переводы — в
  `locales/<язык>.json` (zh, hi, es, fr, ar, pt, ru, de, ja). Язык — `MD2DOCX_LANG`, иначе
  `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG` (кроме `C` и `POSIX`), иначе язык ОС; язык без
  перевода — английский. Ниже сообщения приведены в русском переводе. На stdout по каждому
  файлу одна строка итога, например:
  `Готово: doc.docx — разделов 3 (К, А, К), таблиц 5, из них авто-альбомных 2`
  (по-английски `Done: doc.docx — sections: 3 (P, L, P), tables: 5, auto-landscape: 2`).
- Предупреждения — в stderr с префиксом `Внимание:` (`Warning:`) (пропущенная картинка, HTML-блок,
  таблица не влезла даже в альбомную страницу, маркер внутри списка/цитаты и т. п.).
- `__version__ = "1.2.0"` в `md2docx.py` — единственный источник версии.
- Структура: `main()` разбирает аргументы и вызывает `convert(md_path, out_path, *,
  landscape=False, auto_landscape=True, force=False) -> dict` (статистика для строки
  итога), чтобы конвертер можно было звать и из Python.

Защита от перезаписи и пакет (0.2.0):

- В `docProps/core.xml` результата — метка «наш файл»: `dc:identifier` = `md2docx` (Word её
  не показывает).
- Существующий файл результата перезаписывается без вопросов, только если это docx с этой
  меткой, `cp:revision` = 1 и пустым `cp:lastModifiedBy` (после конвертации не правился).
  Иначе — отказ, код 1: «<out> уже существует и правился после конвертации или создан не
  md2docx — не перезаписываю; чтобы перезаписать, добавьте --force». Файлы от 0.1.0/0.1.1
  (без метки) — тоже отказ: безопасная сторона.
- `--force` — перезаписать без этой проверки. `convert(..., force=False)` делает ту же
  проверку и при отказе бросает `FileExistsError` с текстом на языке интерфейса; CLI печатает его как
  ошибку файла и идёт дальше по пакету.
- Запись атомарная: во временный файл в каталоге результата, затем `os.replace`; при
  ошибке временный файл удаляется. Уточнено в 0.2.0: существующий результат без права
  записи не заменяется и с `--force` — ошибка «нет доступа: <out>», код 1 (замена файла
  обошла бы защиту от записи); если `<out>` — символьная ссылка, она остаётся ссылкой:
  временный файл создаётся рядом с файлом, на который она указывает, и заменяет его.
  Временный файл получает права прежнего результата (`shutil.copymode`), но это новый
  файл: жёсткие ссылки на прежний результат замены не видят. Нужно право записи в каталог
  результата, без него — «нет доступа: <каталог>», код 1. `<out>` — каталог: «это каталог,
  а не файл», код 1, и без `--force`.
- Пакет: если результат входа совпадает с результатом более раннего входа этого же
  запуска (`notes.md notes.markdown` — оба пишут в `notes.docx`; один файл дважды) —
  ошибка для позднего входа (код 1), ранний результат остаётся.

Уточнено в 0.3.0 — файл, открытый в Word, и подсказки шрифтов:

- Замок Word. Перед заменой существующего файла (результат `convert()`, файл `--fix-fonts`):
  если рядом лежит замок Word, файл открыт в Word — отказ, код 1: «<путь>: файл открыт
  в Word (рядом <имя замка>) — закройте его или запустите с --force»; в `convert()` и
  `fix_fonts()` — `FileExistsError` с тем же текстом. Имя замка — по замеру в Word для
  Mac 16.114: основа — имя файла без последнего расширения, `n` — её длина в символах
  после NFC; `n ≤ 6` — `~$` + основа, `n = 7` — `~$` + основа без первого символа,
  `n ≥ 8` — без двух первых; дальше то же расширение. Кандидат один; имена файлов каталога
  сравниваются с ним после приведения к NFC (Word пишет имя замка в NFD) и без учёта регистра
  (APFS регистр не различает: `Report.md` пишет в существующий `report.docx`). Путь —
  символьная ссылка: замок ищется и рядом с ней, и рядом с файлом, на который она указывает
  (заменяется он). Замок проверяется раньше метки md2docx: отказ и для нетронутого
  результата. `--force` — перезапись, как раньше. Файла нет — замок не проверяется. Замок,
  оставшийся после закрытия Word, и замок другого файла с тем же именем (`abcdefgh.docx`
  и открытый `cdefgh.docx`) тоже дают отказ — его снимает `--force`.
- `--fix-fonts FILE.docx [FILE.docx ...]` — не конвертировать, а вернуть в
  `word/fontTable.xml` готового docx подсказки §3.2, которые Word для Mac стирает при
  сохранении: у записей `Helvetica Neue` и `Menlo` поля, которые пишет md2docx (`altName`,
  `panose1`, `charset`, `family`, `pitch`, у Helvetica Neue ещё `sig`), получают значения
  md2docx; недостающие вставляются по порядку схемы, остальные поля записи (`notTrueType`,
  `embed*`) и записи других шрифтов не трогаются. Если шрифт используется (`w:rFonts`
  ascii/hAnsi/cs/eastAsia в `document.xml`, `styles.xml`, `numbering.xml`), а записи о нём
  нет — запись добавляется в конец таблицы шрифтов целиком.
- Прочие члены zip — те же байты, в том же порядке; меняется только `word/fontTable.xml`.
  Запись — как у результата: атомарная, права сохраняются, символьная ссылка остаётся
  ссылкой, файл без права записи — «нет доступа». Замок Word — отказ без `--force`.
  Менять нечего — файл не переписывается (mtime прежний) и замок не проверяется.
- Итог на stdout: `Готово: <файл> — восстановлены подсказки шрифтов: Helvetica Neue
  (altName, family), Menlo (altName)` или `Без изменений: <файл> — подсказки шрифтов на
  месте`. Не zip, битый архив, зашифрованный член, оборванный XML части — «не docx или файл
  повреждён», нет `word/fontTable.xml` — «в файле нет word/fontTable.xml — это не docx»:
  код 1, пакет идёт дальше. Защита от docx-бомбы: член, сжатый не deflate (Word иначе не
  сжимает), — «не docx или файл повреждён»; по заявленным размерам весь архив больше 512 МБ
  в распакованном виде или части, которые разбираются (`fontTable`, `document`, `styles`,
  `numbering`), больше 64 МБ — отказ до распаковки, тоже код 1; член читается не дальше
  заявленного размера. С `--fix-fonts`
  нельзя `-o`, `--landscape`, `--no-auto-landscape` — ошибка аргументов, код 2.
- Python: `fix_fonts(path, *, force=False) -> dict` — `{шрифт: [восстановленные поля]}`,
  пустой словарь — файл не тронут; ошибки — `ValueError`, `FileExistsError`, `OSError`.

## 2. Разбор Markdown

`MarkdownIt("commonmark", {"html": True}).enable(["table", "strikethrough"])`.
Поддерживается: заголовки ATX и setext (H1–H6), абзацы, **жирный**, *курсив*,
~~зачёркнутый~~, `код`, блоки кода (fenced и с отступом), цитаты (в т. ч. вложенные
и с блоками внутри), маркированные и нумерованные списки любой вложенности, таблицы
GFM с выравниванием `:---`, `:---:`, `---:`, ссылки, картинки, горизонтальная линия,
жёсткий перенос (два пробела / `\` в конце строки), `<br>`/`<br/>`/`<br />` (в т. ч.
в ячейках и заголовках), HTML-сущности, экранирование `\|` в таблицах.

- Мягкий перенос строки → пробел.
- YAML front matter (файл начинается с `---`, закрывающая `---` в первых 50 строках,
  между ними строки вида `ключ: значение`) — пропускается, не выводится.
- HTML-комментарии не выводятся. Маркеры (§4) — тоже комментарии.
- Прочие inline-теги удаляются, текст между ними остаётся. HTML-блок, не являющийся
  комментарием: теги вырезаются, оставшийся текст — обычным абзацем + предупреждение.
- Ни один символ разметки (`**`, `__`, `` ` ``, `|---`, `](`, `<!--`, `#` в начале
  заголовка, ограда кода) не должен попасть в текст DOCX.

Уточнено по итогам проверки:

- `maxNesting` = 100: с пресетным 20 разборщик молча отбрасывает остаток файла после
  списка глубины 10 или цитаты глубины 20.
- Символы, недопустимые в XML 1.0 (U+0000–U+0008, U+000B, U+000C, U+000E–U+001F, U+FFFE,
  U+FFFF), вырезаются из md до разбора.
- `</br>` — тоже перенос строки (так его читают браузеры).
- Незакрытый `<!--` — комментарий до конца HTML-блока, то есть до конца файла (как в
  браузере), + предупреждение.
- HTML-блок: содержимое `<script>`, `<style>`, `<template>` вырезается целиком; блочный
  тег (`p`, `div`, `td`, `li`, `summary` и т. п.) разделяет слова; оставшийся текст
  разбирается как inline-Markdown (жирный, ссылки), поэтому разметка в DOCX не попадает.
- Front matter: строка сразу за открывающей `---` не пустая (иначе это линия, как в
  pandoc); внутри, кроме `ключ: значение`, допустимы продолжения с отступом, пункты `- …`
  и комментарии `#`, но хотя бы одна строка — `ключ: значение`.
- Документ без видимого содержимого — одна пустая страница + предупреждение.

Уточнено в 0.2.0:

- Кодировка: файл читается байтами. BOM UTF-8 снимается; BOM UTF-16 LE/BE — файл
  декодируется как UTF-16. Без BOM: есть байт 0 → ошибка, код 1: «похоже на UTF-16 без BOM
  или двоичный файл — сохраните в UTF-8» (UTF-16 без BOM иначе «читается» как UTF-8 и даёт
  мусор вместо текста); иначе строгий UTF-8, при ошибке — «файл не в кодировке UTF-8», код 1.
- Разбор оборвался по `maxNesting` (хвост документа не попал в дерево) — предупреждение
  «часть документа глубже N уровней вложенности пропущена».
- Сноски: строка определения `[^метка]: текст` в начале блока (вне блоков кода) выводится
  обычным абзацем как есть, ссылка `[^метка]` в тексте — как текст. Ни гиперссылок «^1»,
  ни потери текста определения (по CommonMark такая строка с адресом — определение ссылки
  и пропала бы). Настоящих сносок Word нет.
- Front matter, закрытый строкой `...` (как в YAML), — тоже front matter.
- Незакрытый `<!--` внутри строки абзаца — текст остаётся, + предупреждение.
- Inline `<script>…</script>`, `<style>…</style>`, `<template>…</template>` в абзаце —
  содержимое не выводится (как в HTML-блоке).
- `&#11;`, `&#12;` и такие же символы прямо в тексте (U+000B, U+000C) — пробел, а не
  склейка слов (вырезание недопустимых в XML символов выше их не касается).
- Двойной пробел на месте вырезанного комментария (например, в конце выделенного
  фрагмента) схлопывается в один.
- Документ только из невидимых блоков (в т. ч. из одних `<br>`) — то же предупреждение
  «нет видимого содержимого».

## 3. Оформление (эталон)

Единицы: twips (1/20 pt; 567 twips = 1 см), размеры шрифта — полупункты (`w:sz`).

### 3.1 Страница

| Параметр | Значение |
|---|---|
| Формат | A4: 11906 × 16838 (книжная), 16838 × 11906 (альбомная, `w:orient="landscape"`) |
| Поля | 1134 (2,0 см) со всех сторон в обеих ориентациях |
| Колонтитулы | отступ header/footer 720; самих колонтитулов и номеров страниц нет (как в эталоне) |
| Ширина текста | книжная 9638, альбомная 14570 |

Каждый раздел задаётся явно (шаблон python-docx по умолчанию — Letter с полями
3,17/2,54 см, это надо перебить в каждом разделе).

### 3.2 Документ по умолчанию (`docDefaults`) и `settings.xml`

- Шрифт: `w:rFonts` ascii/hAnsi/cs = `Helvetica Neue`, eastAsia = `Times New Roman`
  (без theme-атрибутов). Размер 22 (11 pt), `szCs` 22. Язык — по тексту (1.2.0): есть
  кириллица в тексте документа — `ru-RU`, иначе `en-US` (`w:lang val` и `eastAsia` — этот язык,
  `bidi="ar-SA"`); до 1.2.0 — всегда `ru-RU`. Решает текст, попавший в документ (`w:t`):
  front matter, HTML-комментарии, адреса ссылок и картинок не в счёт, надпись заглушки
  картинки (§3.6, на языке интерфейса) — тоже, её подпись (alt) — в счёт.
- Абзац: `spacing after=160 line=278 lineRule=auto`, `widowControl`. Выравнивание — влево
  (по ширине НЕ выравнивать).
- Стиль `Normal` — без собственных переопределений.
- `settings.xml`: `compatibilityMode` = 15 (иначе Word рисует таблицу со сдвигом в левое
  поле и показывает «Режим совместимости»).
- `fontTable.xml`: запись для `Helvetica Neue` с `w:altName="Arial"`,
  `panose1=02000503000000020004`, `family=swiss`, `pitch=variable`; для `Menlo` —
  `altName="Consolas"`, `family=modern`, `pitch=fixed`. Нужна, чтобы Word на Windows,
  где этих шрифтов нет, подставил гротеск, а не антикву. Шрифт — Helvetica Neue, как
  в эталоне; документ обязан корректно открываться в Word на Windows (§6).
  Вёрстка не должна зависеть от подмены. Уточнено по итогам проверки: Arial не везде
  уже Helvetica Neue (курсивная «т», скобки, кавычки шире), поэтому ширины колонок
  считаются по бо́льшему из двух замеров (§3.4 п. 2). Уточнено в 0.3.0: Word для Mac при
  сохранении стирает `altName` и меняет класс Helvetica Neue на `auto` — `--fix-fonts` (§1)
  возвращает эти записи в готовый docx.
- Свойства документа: `title` — текст первого H1 без разметки (нет H1 или первый H1
  пустой — имя файла без расширения; уточнено по итогам проверки); `author`, `last_modified_by`, `comments`, `subject`, `keywords` — пустые
  (шаблон python-docx пишет туда «python-docx» — убрать); `revision` = 1.
  Уточнено в 0.2.0: `title` не длиннее 255 символов — длинный H1 обрезается (начало H1),
  конвертация не падает; `dc:identifier` = `md2docx` (§1).
- Символ, которого нет в Helvetica Neue, но есть в Arial (пример: `→` U+2192 — Word для Mac
  рисует его Times New Roman), — отдельным прогоном с `rFonts` ascii и hAnsi = `Arial` (как
  маркеры списков, §3.5); в таком прогоне — только такие символы и пробелы. Нет ни там, ни
  там — не трогать. Код (Menlo) не трогать. Наличие глифа — Pillow: отрисовка символа
  отличается от отрисовки заведомо отсутствующего кодпоинта (кеш по символу), без fontTools.
  Уточнено в 0.2.0.

### 3.3 Заголовки

Встроенные стили Word `Heading 1…6` (styleId `Heading1…6`) — чтобы работали панель
навигации и оглавление. Шаблонные значения python-docx (тема `majorHAnsi`, синий цвет,
`after=0`) перебиваются полностью: шрифт явный `Helvetica Neue`, цвет авто (никакого
`w:color`), полужирный, `keepNext`, `keepLines`, `after=160`, `outlineLvl` = уровень−1.

| Уровень | `w:sz` | before | Прочее |
|---|---|---|---|
| H1 | 36 (18 pt) | 360 | — |
| H2 | 32 (16 pt) | 300 | — |
| H3 | 28 (14 pt) | 260 | — |
| H4 | 24 (12 pt) | 240 | экстраполяция |
| H5 | 22 (11 pt) | 220 | экстраполяция |
| H6 | 22 (11 pt) | 200 | курсив; экстраполяция |

Inline-разметка внутри заголовка сохраняется; `<br>` даёт перенос строки (`w:br`).
Автонумерации заголовков нет — номера берутся из текста md как есть.
Уточнено в 0.2.0: inline-код в заголовке — кеглем заголовка (Menlo и заливка остаются;
прямого `w:sz`, отличного от размера стиля заголовка, у прогона нет); вне заголовков —
`sz=20`, как в §3.6.

### 3.4 Таблицы — главный предмет

| Параметр | Значение |
|---|---|
| Ширина | `tblW type=dxa` = ширина текста раздела минус отступ (§3.8); сумма `gridCol` равна ей ровно |
| Раскладка | `tblLayout type=fixed`; каждая ячейка `tcW type=dxa` = её `gridCol` |

Изменено в 0.3.0: `tblHeader` не ставится ни одной строке — на следующих страницах шапка не повторяется (в 0.1.0–0.2.0 повторялась). Уточнено в 0.2.0: если все ячейки шапки в md пусты (нет видимого текста и картинок), строки шапки в docx нет — таблица начинается с тела: у первой строки нет заливки шапки; ширины колонок — по телу |

Уточнено по итогам проверки |
| Удержание строк | уточнено в 0.2.0: `keepNext` на абзацах строки шапки и первой строки тела (таблица не начинается внизу страницы одной шапкой или шапкой с одной строкой) и на абзацах предпоследней строки (последняя строка не уходит одна на новую страницу). Внутри цитат и списков отбивки нет |

Уточнено в 0.2.0: если документ кончается таблицей, последний абзац — носитель 1 pt, как у разрыва раздела (`before=0 after=0 line=20 lineRule=exact`, знак абзаца `sz=2`), а не разделитель 8 pt: иначе таблица, дошедшая до низа страницы, даёт пустую последнюю страницу. Так же при разрыве страницы за таблицей: разделителем служит абзац с `pageBreakBefore` (следующий блок или носитель 1 pt перед следующей таблицей), разделитель 8 pt не добавляется — у таблицы, дошедшей до низа страницы, он ушёл бы на новую страницу, и та осталась бы пустой |
| Разрыв внутри таблицы | добавлено в 0.3.0: строка `\newpage` или `\pagebreak` между строками тела (по GFM она стала бы строкой таблицы) режет таблицу по целой строке. Строки над разрывом — первая часть с шапкой, под ним — следующая часть: отдельная таблица с новой страницы (между частями — только абзац с `pageBreakBefore`, разделителя 8 pt нет), без шапки (`firstRow=0`, `val=0480`, без заливки и полужирного). Сетка у частей одна: ширины колонок считаются по всем строкам таблицы, `gridCol` и `tblW` у частей одинаковые. Удержание строк — у каждой части своё, по её строкам. Несколько разрывов — несколько частей; разрывы подряд (серия) — один разрез. Автоальбомность, подтягивание и склейка (§4.3) — по таблице целиком: все части в одном разделе. Разрыв сразу под строкой-разделителем — разрыв страницы перед таблицей, таблица целиком. Если под разрывом (под серией) таблица кончается, начинается новая таблица со своей строкой-разделителем или идёт строка без `|`, — это разрыв после таблицы, как в 0.2.0 (§4.1): строка без `|` — текст после таблицы, хотя по GFM она тоже стала бы строкой. В таблице внутри списка или цитаты разрыв игнорируется с предупреждением, как маркер (§4.1); строкой таблицы он не становится |

Строки короче шапки дополняются пустыми ячейками, лишние ячейки отбрасываются (как в GFM).

**Ширина колонок** (по типу CSS auto-layout):

1. Для каждой колонки `j` измерить по всем её ячейкам (шапка — полужирным):
   - `max_j` — ширина самой длинной строки ячейки без переносов (строки делятся по `<br>`)
     + 216 (поля ячейки 108+108);
   - жёсткий минимум `hard_j` — ширина самого длинного куска слова между местами
     переноса + 216;
   - мягкий минимум `soft_j` — ширина самого длинного слова целиком, по дефисам не
     делится, + 216; `soft_j ≥ hard_j`.
   Слово — кусок между пробелами; пробелами считаются и U+2002, U+2003, U+2009, U+200B
   (ZWSP). Уточнено в 0.2.0 — места переноса внутри слова, как переносит LibreOffice
   (UAX #14): после `‐ – —` — всегда; после ASCII `-` — всегда, кроме сочетания «не цифра,
   дефис, цифра». `информационно-телекоммуникационной` → `информационно-` и
   `телекоммуникационной`; `2026-10-22` → после `2026-` и после `10-`; `АБ-2026-001` →
   только после `2026-`; `Ф-123456` не делится. Прототип регулярного выражения мест
   переноса: `(?<=[‐–—])|(?<=-)(?!\d)|(?<=\d-)`.
   URL (слово с `://` или `www.`) по дефисам не делится ни в одном минимуме; URL не
   длиннее 30 символов учитывается целиком (уточнено в 0.2.0: короткий адрес иначе
   разорвётся), длиннее — не учитывается. Прочие куски длиннее 30 символов (хэши, длинные
   коды) в минимумах не учитываются — их Word перенесёт посимвольно, это допустимо.
2. Замер — Pillow `ImageFont.truetype(...).getlength()` по реальному шрифту:
   `/System/Library/Fonts/HelveticaNeue.ttc` индексы 0 Regular, 1 Bold, 2 Italic,
   3 Bold Italic; код — `/System/Library/Fonts/Menlo.ttc`. Запасной путь — Arial
   (`/System/Library/Fonts/Supplemental/Arial*.ttf`, `C:\Windows\Fonts\arial*.ttf`),
   последний — эвристика 0,55 em на символ (полужирный 0,60 em). К замеру +3 % запаса.
   Уточнено по итогам проверки: текст (не код) меряется и по HN, и по Arial, берётся
   бо́льшая ширина — Arial у части глифов шире HN (курсивная «т», скобки, кавычки), и
   при его подстановке в Word на Windows слово в узкой колонке иначе рвётся.
   Проверено на строке шапки таблицы эталона, Bold 11 pt: по Pillow — 166,7 pt, в Word — 58,8 мм.
3. Доступная ширина `W`. Уточнено в 0.2.0 — нижняя граница колонки `lo_j`: если
   `Σsoft ≤ W` — `soft_j` (даты и коды остаются целыми), иначе `hard_j`. Влезает ли
   таблица без разрыва слов (автоальбомная §4.3, предупреждение «не влезает») — решает
   только `Σhard`: от мягкого минимума ориентация не меняется никогда.
   - `Σmax ≤ W` → `w_j = max_j + (W − Σmax) · max_j / Σmax`;
   - иначе `Σlo ≤ W` → по объёму текста (уточнено в 0.2.0): объём колонки `v_j` — сумма
     ширин ячеек тела в одну строку (та же величина, что для `max_j`, без полей; шапка не
     считается). Свободные колонки делят остаток ширины пропорционально `v_j`; если
     колонке досталось меньше `lo_j` — закрепить её на `lo_j` и пересчитать; иначе если
     больше `max_j` — закрепить на `max_j` и пересчитать. Если у всех колонок `v_j = 0` —
     прежняя интерполяция `w_j = lo_j + (W − Σlo) · (max_j − lo_j) / Σ(max − lo)`;
   - иначе (`Σhard > W`) таблица не влезает без разрыва слов: кандидат в автоальбомную
     (§4.3); если уже альбомная или авто выключено — `w_j = min(hard_j, T)`, где порог `T`
     подобран так, что `Σ w_j = W`, + предупреждение: узкие колонки (номера, даты)
     сохраняют своё самое длинное слово, рвутся только слова самых широких колонок.
     Уточнено по итогам проверки (раньше `W · min_j / Σmin` рвало самое длинное слово
     в каждой колонке).
4. Ширины — целые twips; остаток от округления отдать самой широкой колонке; сумма = `W` ровно.

### 3.5 Списки

Настоящая нумерация Word (`numbering.xml`), не текстовые маркеры.

- Свои `abstractNum`: маркированный (уровни по кругу `•`, `◦`, `▪`) и нумерованные
  `decimal` с `lvlText` `%N.` (и отдельный для разделителя `)`). Отступы уровня `i`
  (0…8): `left = 360·(i+1)`, `hanging = 360`.
- Каждый список md (каждый `bullet_list_open` / `ordered_list_open`, включая вложенные)
  получает свой `w:num` с `lvlOverride/startOverride` = номер начала списка на его
  уровне. Так соседние списки не продолжают нумерацию друг друга, а `3.` в md даёт 3.
- Абзац пункта: стиль `Normal` + `numPr` (`ilvl` = глубина вложенности). Интервал после
  пункта 80, у последнего пункта внешнего списка — 160.
- Уточнено по итогам проверки: уровней в Word 9, поэтому пункты глубже девятого получают
  `ilvl` 8 (отступ текста — по глубине, но не больше 8 уровней, §3.8). У уровней маркированного списка
  `rPr/rFonts` = Arial: глифов `◦` и `▪` в Helvetica Neue нет, иначе их рисует запасной
  шрифт другого размера; Arial есть и на Mac, и на Windows.
- Второй и следующие абзацы пункта — без `numPr`, с отступом текста пункта (`left = 360·(i+1)`).

### 3.6 Цитаты, линия, код, ссылки, картинки

- **Цитата** (`>`): стиль `Quote`, переопределённый под эталон: `pBdr left single sz=18
  space=8 color=DDDDDD`; `ind left=360` на каждый уровень вложенности; `before=160
  after=160 line=276 auto`; курсив; цвет `555555`. Списки и таблицы внутри цитаты
  получают отступ цитаты.
- **Горизонтальная линия** (`---`): пустой абзац с `pBdr bottom single sz=6 space=1
  color=BBBBBB` (как в эталоне).
- **Код inline**: шрифт `Menlo`, `sz=20`, `shd clear auto F2F2F2`; в заголовке — кеглем
  заголовка (§3.3).
- **Блок кода**: один абзац, строки через `w:br`, пробелы и табы сохраняются
  (`xml:space="preserve"`), `Menlo` `sz=20`, заливка абзаца `F2F2F2`, `before=0
  after=160 line=240 auto`, выравнивание влево. Уточнено в 0.2.0: текст отступает от
  краёв серой плашки — рамки цвета заливки слева и справа с `w:space` либо иной способ,
  который Word и LibreOffice показывают одинаково; между соседними блоками кода виден
  промежуток (раньше они сливались в одну плашку); строки одного блока — одна плашка.
- **Ссылка**: настоящая гиперссылка (`w:hyperlink` + внешняя связь `r:id`) со стилем
  символов `Hyperlink` (создать: цвет `0563C1`, подчёркивание `single`). Уточнено
  в 0.2.0 — гиперссылка только для схем `http:`, `https:`, `mailto:`, `tel:` (без учёта
  регистра). Остальное — текст ссылки без гиперссылки, форматирование текста сохраняется:
  относительные пути и якоря `#...` — молча; `file:`, `data:`, `smb:`, `ms-msdt:`,
  `javascript:` и любые другие схемы — с предупреждением (адрес в нём обрезан примерно
  до 60 символов).
- **Картинка**: локальный файл (путь относительно md) вставляется в строку, ширина не
  больше доступной ширины текста, пропорции сохраняются (96 dpi). Нет файла или URL
  удалённый → курсивная серая заглушка `[изображение: alt]` (на языке интерфейса,
  по-английски `[image: alt]`) + предупреждение.
  Уточнено по итогам проверки: файл, который не читается как картинка (битый, SVG), —
  та же заглушка + предупреждение, конвертация продолжается. Картинка в ячейке таблицы
  участвует в ширине колонки (§3.4 п. 1): `max_j` — её натуральная ширина, `min_j` — не
  меньше min(натуральная, 3 см = 1701); заглушка меряется как текст.
  Уточнено в 0.2.0:
  - масштаб — ширина не больше ширины места, высота не больше 0,8 высоты текстовой
    области ориентации раздела (книжной 14570, альбомной 9638), пропорции сохраняются;
    так же в ячейке. Натуральная ширина для колонок (`max_j`, `min_j`) — с тем же
    ограничением по высоте;
  - файл больше 50 МБ не читается: заглушка + предупреждение;
  - картинка вне каталога md (путь ведёт выше или абсолютный в другое место) —
    вставляется, но с предупреждением «картинка вне каталога документа»;
  - `file:` — как локальный файл;
  - в предупреждениях имя файла раскодировано из %-кодировки, `data:` URI обрезан
    (около 40 символов + «…»);
  - в alt сущности и `\`-экранирование сохраняются: `&amp;` → `&`, `\*` → `*`.

### 3.7 Inline

`w:b`, `w:i`, `w:strike`; комбинации накладываются. Жёсткий перенос и `<br>` → `w:br`.

### 3.8 Отступы вложенных блоков

Контейнер (цитата, пункт списка) сдвигает вложенные блоки: абзацы — через `ind left`,
таблицы — через `tblInd`, при этом ширина таблицы = ширина текста раздела − отступ.

Уточнено в 0.2.0: отступ уровней списков и цитат ограничен 8 уровнями (8 × 360); глубже —
на отступе 8-го уровня. Поэтому ширина таблицы в глубокой вложенности не бывает
отрицательной или меньше разумного минимума, а текст не уходит за правое поле.

## 4. Ориентация страниц

### 4.1 Маркеры

Отдельной строкой (HTML-блок верхнего уровня), регистр и пробелы внутри не важны:

- `<!-- landscape -->` — с новой страницы альбомная ориентация;
- `<!-- portrait -->` — с новой страницы книжная;
- `<!-- pagebreak -->`, а также строки `\newpage` и `\pagebreak` — разрыв страницы.

Правила: маркер той же ориентации, что текущая, — ничего не делает (ни пустого раздела,
ни пустой страницы). Маркер до первого содержимого задаёт ориентацию первого раздела без
разрыва. Несколько маркеров подряд — серия (уточнено в 0.2.0, см. ниже). Маркер после последнего
содержимого игнорируется. Маркер внутри блока кода — это текст кода. Маркер внутри
списка или цитаты игнорируется с предупреждением.

Уточнено по итогам проверки:

- «Пробелы внутри не важны» — это пробелы вокруг слова: `<!--  Landscape -->` — маркер,
  `<!-- land scape -->` — обычный комментарий.
- Блок без видимого содержимого (нет ни текста, ни картинки, ни таблицы, ни линии: пустая
  цитата, цитата из одного комментария, `<br>`, `&nbsp;`, пустой `#`) содержимым не
  считается: маркеры вокруг него действуют как стоящие подряд, а сам он раздела не
  открывает — уходит в раздел видимого соседа.
- Маркер ориентации начинает новую страницу и тогда, когда автоальбомная таблица (§4.3)
  сделала ориентацию соседних участков одинаковой.

Уточнено в 0.2.0:

- Серия маркеров подряд (между ними нет видимого содержимого): ориентация и разрыв
  копятся раздельно — ориентация берётся у последнего из маркеров ориентации, разрыв
  есть, если в серии был хоть один разрыв. Маркер ориентации рядом с `\newpage` не теряет
  ориентацию; `\newpage` перед маркером той же ориентации даёт разрыв. Новый раздел и так
  начинается с новой страницы — второй разрыв не добавляется.
- Строка `\newpage` или `\pagebreak` сразу под строкой таблицы (без пустой строки) —
  разрыв страницы, а не строка таблицы (по GFM она стала бы строкой); маркеры-комментарии
  таблицу и так закрывают.
- Экранированные `\\newpage` и `\\pagebreak` в исходнике — текст, не разрыв. Так же
  запись через сущность (`&#92;newpage`, `&bsol;newpage`): разрыв — только строка,
  которая в исходнике дословно `\newpage` или `\pagebreak`.

Уточнено в 0.3.0:

- Строка `\newpage` или `\pagebreak` между строками тела таблицы режет таблицу на части
  (§3.4, «Разрыв внутри таблицы»). Разрыв страницы после таблицы — если под строкой-разрывом
  (под серией таких строк) таблица кончается, начинается новая таблица со своей
  строкой-разделителем или идёт строка без `|`.

### 4.2 Флаг

`--landscape` задаёт ориентацию по умолчанию (до первого маркера).

### 4.3 Автоальбомная ориентация

Таблица (или блок верхнего уровня, содержащий такую таблицу), которая на книжной
странице не укладывается без разрыва слов (`Σhard > W_книжн`, §3.4), сама уходит в
альбомный раздел — только внутри книжных участков (по умолчанию или после
`<!-- portrait -->`); участки, размеченные альбомными, не трогаются.
С `--no-auto-landscape` выключено.

- **Подтягивание** (уточнено в 0.2.0 — единое правило вместо «подпись с двоеточием +
  заголовки подряд»). От блока с первой широкой таблицей группы идём назад; невидимые
  блоки (§4.1) прозрачны — пропускаются и уходят вместе с диапазоном.
  1. Подпись — абзац, оканчивающийся двоеточием, прямо перед таблицей — забирается всегда.
  2. Подводка — дальше назад не больше 2 коротких простых абзацев (не длиннее 600 символов
     видимого текста, без картинок) и не больше 1 горизонтальной линии, в любом порядке.
     Если за ними (назад) стоит заголовок — подводка забирается вместе с заголовком; если
     нет — остаётся на месте (забирается только подпись).
  3. Заголовки — заголовок и все заголовки прямо над ним (подряд, невидимые пропускаются)
     забираются; `top` — самый старший (наименьший) уровень среди забранных.
  4. Подъём — снова назад: не больше 2 коротких простых абзацев и 1 линии; если за ними
     стоит заголовок строго старшего уровня, чем `top`, — забрать их, его и заголовки
     прямо над ним, обновить `top` и повторить п. 4; иначе стоп.
  5. Стоп всегда: разрыв страницы, начало участка (явный маркер), список, цитата, код,
     таблица, HTML-блок с текстом, абзац с картинкой или длиннее 600 символов, в п. 4 —
     заголовок уровня не старше `top`, третий абзац или вторая линия.

  Заголовок с коротким вступлением не остаётся внизу книжной страницы, оторванный от
  своей таблицы. Пример: `samples/04` даёт разделы «альбомный, книжный» — H1, вступление,
  H2 и подпись уходят на альбомную страницу вместе с таблицей (раньше H1 и вступление
  оставались одни на книжной странице).
- **Склейка**: если между двумя автоальбомными группами не больше двух видимых блоков
  верхнего уровня (невидимые не считаются, уточнено в 0.2.0), среди них нет таблиц и нет
  разрыва страницы — они объединяются в один альбомный раздел.
- После группы — возврат к ориентации участка с новой страницы.

### 4.4 Разделы

Разрыв раздела — `nextPage`. python-docx (`document.add_section`) кладёт `sectPr`
предыдущего раздела в новый пустой абзац-носитель; его надо обнулить: `before=0 after=0
line=20 lineRule=exact`, знак абзаца `sz=2`. Иначе при полностью заполненной странице
появляется пустая страница. Ни одного пустого раздела и ни одной пустой страницы.
Каждый раздел явно получает A4, ориентацию и поля из §3.1.

## 5. Корректность OOXML

python-docx или вставкой на правильную позицию, но не `append` наугад):

## 6. Проверка (критерии готовности)

- `tests/verify.py` — независимый сверщик md ↔ docx (пишется по этой спецификации, без
  взгляда на реализацию): мультимножество слов, последовательность заголовков (уровень +
  текст), число таблиц, размеры и тексты ячеек, отсутствие остатков разметки, инварианты
  §3–§5 (раздел A4 и ориентация, поля; ширина таблицы = ширине текста раздела; `tcW` =
  `gridCol`; `tblHeader` (уточнено в 0.3.0: ни у одной строки), `cantSplit`, заливка и
  жирность шапки; стили заголовков; `docDefaults`; порядок элементов §5; нет пустых
  разделов). Код выхода ≠ 0 при расхождении.
  Уточнено в 0.2.0 — сверщик читает md так же, как конвертер (§2: кодировки и отказ на
  UTF-16 без BOM, front matter, сноски как текст, `&#11;` и `&#12;`, сущности в alt,
  предупреждение об обрыве по `maxNesting`), и проверяет ещё:
  - порядок слов — последовательность, а не только набор;
  - план разделов и разрывов по маркерам и правилам §4.1 и §4.3 (ориентации разделов,
    подтягивание, склейка); разрыв страницы засчитывается и новым разделом той же
    ориентации;
  - таблицы: без шапки, отбивку после заголовка, `keepNext`, хвост 1 pt (§3.4);
    ширины положительны, сумма равна ширине текста, каждая колонка не уже нижней границы
    `lo_j` (при `Σsoft ≤ W` даты и коды целиком), при `Σhard > W` узкие колонки целиком;
    картинки в ячейках участвуют в минимуме;
  - гиперссылки — только схем §3.6, те же адреса и в том же порядке, что в md;
  - символы без глифа в Helvetica Neue — в прогонах Arial (§3.2);
  - `dc:identifier`, `title` не длиннее 255 символов (§3.2), кегль inline-кода в
    заголовке (§3.3);
  - отступ абзацев и таблиц не глубже 8 уровней (§3.8), размер картинок (§3.6).
  Уточнено в 0.3.0: части таблицы, разрезанной `\newpage` (§3.4), сверщик находит своим
  разбором md и проверяет: у частей одна сетка (`gridCol`, `tblW`), минимумы колонок — по
  всем частям, шапка только у первой, разрыв страницы перед каждой следующей частью и перед
  таблицей при разрыве под строкой-разделителем; `tblHeader` нет ни у одной строки; хвост
  цепочки `keepNext` — во всю область текста.
- `tests/test_md2docx.py` (pytest) гоняет все `samples/*.md` через CLI и сверщик плюс

- Свои реальные документы, необязательно (пути — в `tests/real_docs.local.txt`, файл в `.gitignore`,

- Совместимость с Windows: (а) по официальной документации Microsoft подтвердить, как
  Word для Windows подбирает замену отсутствующему шрифту и какие поля `fontTable`
